# mysql_perf_8.0.json — curated performance knob file

Generated by [`scripts/curate_knob_file.py`](../scripts/curate_knob_file.py) from
`mysql_all_8.0.json` (186 knobs) → **117 knobs (88 integer, 29 enum, 68 enum choices)**.
Validated against the local mysqld 8.0.44 binary (0 dropped by `validate_knob_file.py`).
Built for the source-sample-collection experiment but intended as the reusable
"all perf-relevant MySQL 8.0 knobs" file — **the later target tuning runs must use this
same file** so history configs reconstruct exactly (OtterTune exact-config matching;
silent skip in `history_container.load_history_from_json` otherwise).

## Curation rule (conservative, per user request)

A knob is dropped **only if the reason is workload-independent** — it would never be a
performance trade-off under ANY repo workload (sysbench, oltpbench/TPCC/twitter, JOB,
TPC-H). Sysbench-specific no-ops are KEPT (full-text, DDL-time-only, GIS, stored programs,
optimizer-stats knobs, `join_buffer_size`, ...) — they waste a little sweep budget on
sysbench but stay meaningful for the other workloads. Exception: MyISAM-specific knobs
ARE dropped — every repo workload is InnoDB, and in 8.0 internal disk temp tables and
system tables are InnoDB too (the engine-agnostic `flush`/`flush_time` are kept).

## Deliberately kept (incl. sysbench no-ops, for other workloads)

- All durability/perf trade-offs: `innodb_flush_log_at_trx_commit`, `sync_binlog`,
  `innodb_doublewrite`, binlog group-commit/cache/format knobs, buffer/IO/flushing/
  purge/concurrency knobs, per-session buffers, optimizer knobs.
- Full-text `innodb_ft_*`/`ft_*` (13), engine-agnostic sync knobs `flush`/`flush_time`, DDL-time
  (`innodb_sort_buffer_size`, `innodb_fill_factor`, compression knobs, ...; 12),
  misc feature knobs (`group_concat_max_len`, `stored_program_cache`,
  `innodb_stats_method/on_metadata/include_delete_marked`, `innodb_table_locks`,
  `host_cache_size`, `max_points_in_geometry`; 8).

## Notes / risks

- 6 kept knobs have max > sys.maxsize and get the ÷1000 ConfigSpace scaling
  (`max_binlog_cache_size`, `max_binlog_stmt_cache_size`, `max_seeks_for_key`,
  `innodb_max_undo_log_size`, `group_concat_max_len`, `innodb_online_alter_log_max_size`).
- `innodb_io_capacity` (max 2M) can exceed `innodb_io_capacity_max` (max 40k): mysqld
  auto-adjusts at startup rather than failing, but `[KNOB-VERIFY]` may log mismatches.
  Same for `innodb_buffer_pool_size` chunk rounding and `innodb_page_cleaners` capping.
- Budget impact: sweep N at 5 levels = **451** (earlier cuts: 369 @ 89, 529 @ 135, 490 @ 125 knobs).
